# bf-416c — is_error:true transcripts silently reported as success

## Root cause
A Claude Code turn whose transcript `result` event reported `is_error: true`
(rate limit, tool failure, any assistant-side error) was emitted to callers as
a normal success: exit 0, `"is_error": false` in JSON, captured text as
`result`. The `ClaudePrintError::AssistantError` variant existed and was unit
tested, but no real code path ever constructed it — `read_transcript` returned
`Ok` for `is_error:true` transcripts, `Session::run_inner` never inspected the
flag, and `main.rs` had no arm for it, so it fell into the generic `Setup`
(exit 2) fallback — or, on the success path, `emit_success` hardcoded
`"is_error": false`.

This breaks drop-in exit-code compatibility with `claude -p` (exit 1 on
assistant error) and would cause NEEDLE (which gates retry/success on exit code
+ `is_error` via its `output_transform`) to silently treat failed turns as
success.

## Fix
1. **`src/error.rs`** — added `Error::AssistantError(String)` to the internal
   enum and mapped it through `From<Error> for ClaudePrintError` to
   `ClaudePrintError::AssistantError` (exit 1), instead of the `Setup` catch-all
   (exit 2).
2. **`src/session.rs`** — in the `FifoPayload` arm, after `read_transcript`
   succeeds, check `transcript.is_error`; if true, return
   `Err(Error::AssistantError(transcript.text))`. This `return` drops
   `stream_json_handle` before it goes out of scope, so the reader is joined
   without draining (INV-8, exit-immediately-on-error) — same pattern as the
   `?` propagations in that block.
3. **`src/main.rs`** — added an explicit `Err(Error::AssistantError(msg))` arm
   that emits via `ClaudePrintError::AssistantError(msg)` and exits with
   `exit_code()` (1), ahead of the generic `Err(e)` fallback.
4. **`src/emitter.rs`** — `emit_success` now reads `result.is_error` instead of
   hardcoding `false` (defense in depth; normally unreachable with the fix).

## Verification (DoD)
- `cargo build` — clean.
- `cargo test` — all pass. New/rewritten bf-416c tests:
  - `error::tests::error_to_claude_print_error_assistant_error` — `From<Error>`
    maps `Error::AssistantError` → exit-1 `ClaudePrintError`, not `Setup`.
  - `scenarios::is_error_transcript_maps_to_assistant_error_json` — rewritten to
    drive the real `Error::AssistantError` → `From` impl → `ClaudePrintError`
    path (was hand-constructing the variant = false coverage) and asserts
    `exit_code() == 1`.
  - `parse_transcript_reflects_is_error_true` /
    `read_transcript_preserves_is_error_true` — pin the upstream contract that
    `is_error:true` surfaces on `TranscriptResult` for session.rs to act on.
  - `test_json_is_error_reflects_transcript_flag` — emit_success surfaces the
    real flag.
- `cargo clippy --all-targets` — clean.
- `cargo fmt --check` — clean.

## Scope note
This commit also carries the interdependent `bf-uj0` headless-launch safety
work (`LaunchOptions`, `ChildCapture`, `--pretrust-cwd`/`--mcp-config`/
`--show-child-stderr`, and the `StreamJsonHandle` RAII `Drop` refactor). The two
beads share `session.rs` / `main.rs` / `emitter.rs` and the reader-cleanup
refactor that bf-416c's error path depends on (`drop(stream_json_handle)` only
joins the reader because of that `Drop` impl), so they could not be committed
separately without breaking the build. Both beads are assigned to the same
worker.
